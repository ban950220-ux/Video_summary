# Full coverage Groq summary patch (local fixture verified; review required)

The section-only description below is superseded by [FULL_COVERAGE_GLOBAL_DELTA.md](FULL_COVERAGE_GLOBAL_DELTA.md). The current local patch adds a separate hierarchical AI synthesis stage and a fresh imported-transcript job. The new work has not been deployed or sent to a provider.

Base commit: `18e14727ee34ebb65a36f48f35aefced17adefe3`. This checkout is an isolated local clone. No production schema, credential, approval, provider, or deployment operation was run.

`src/groq-full-coverage.mjs` provides a separate summary contract. It reads and validates the saved source and eight existing raw reports through `planPersistedFullCoverage`; the original `raw:8` failure and its usage remain intact. Its replacement call has a new operation key and requires a separate explicit acknowledgement. The remaining source is partitioned by the exact serialized strict JSON request size. Each new request reserves at most 6,200 UTF-8 request bytes plus 700 completion tokens, below the local 7,000 TPM reservation. The module uses 61 seconds between calls and 195,000 tokens per rolling 24 hours. The request sends every source text and ID; per-segment times remain in the saved source and are recovered by ID, while the request includes the span's start and end times. The reservation is a conservative app estimate; only a verified provider receipt can establish actual usage, and provider account remaining remains unknown. A limit blocks and later resumes from saved stages without resetting old generations.

The final report is a chronological collection of all validated section reports. It is **not** a separate global AI synthesis; `globalSynthesisStatus` says so in the stored report and export. It requires consecutive source IDs, a chapter reference at the first and last ID of every new section, existing-reference checks, and numeric/quote grounding checks. It records the old uncertain outcome as uncertain and labels human semantic review as pending. `markdownReport` renders the coverage audit and original held source. The stored transcript remains part of the standard TXT export.

`src/groq-full-coverage-d1.mjs` now supplies the D1 store. It claims one stage with a unique operation ID and SQL guards for the exact source/audit, approval, held failures and matching usage, deletion, global Groq in-flight state, rolling minute/day reservation, and approval request count. The adapter checks the credential identity and fresh Free organization binding before claim and immediately before provider fetch. Its last D1 query before dispatch checks the exact source, audit, approval, held failures, saved legacy checkpoint and recovery rows, and legacy usage rows. Migration `0016_full_coverage_write_lock.sql` blocks source/audit/proof writers while a full-coverage call is claimed or its receipt remains unsettled; the final dispatch query refuses to proceed without all eleven triggers. It stores the complete response and usage in `RECEIPT_STORED` before adding one deterministic usage event and marking DONE. If that second write fails, the `recover-receipt` action validates the stored response and usage and settles without a new provider request. A lost ACK reads D1 rather than dispatching again. A `BLOCKED` claim from a confirmed pre-dispatch guard failure can be reopened only under a newer approval and an explicit no-call request: a separate durable review row records the prior block before its zero-provider claim is removed. Claims with an uncertain dispatch outcome cannot use this path. `jobs.report_json` is written with an exact source/audit, legacy proofs, new DONE receipt JSON and usage proofs, and all-stages-DONE guard in one CAS, then reread. Existing raw:8 failed operations and usage are never overwritten.

`src/groq-full-coverage-live.mjs` exposes owner-scoped `GET/POST /api/jobs/:id/groq-full-coverage` for status, explicit bounded approval, one foreground stage, stored-receipt recovery, pre-dispatch block review, and finalization. `web/site/app.js` renders these steps, including daily wait and next-day resume. The POST route is disabled unless `ENABLE_FULL_COVERAGE=true` and a fresh protected `GROQ_FREE_ORG_BINDING_JSON` ties the current credential fingerprint to an observed Free, billing-disabled organization. That variable is absent in production and was not registered here. The service thus cannot send a model request from this patch as deployed without a separate review and configuration change. Account remaining is always UNKNOWN; the app reservation is not a Groq account-side hard billing control.
