# Global synthesis and fresh transcript delta

This is an isolated local code patch based on `18e14727ee34ebb65a36f48f35aefced17adefe3`. No production setting, key, D1 row, deployment or provider was changed. Every model response in the tests is a fixture.

## Existing job

The stored 1,226 segment audio transcript, eight validated old raw checkpoints, raw:8's two uncertain failures and all past usage remain separate and immutable. The route checks the actual saved audit, source, historical operation IDs and usage before each new leaf. A mismatch, including the live `SUMMARY_RECOVERY_SCOPE_CHANGED`, blocks before any provider call. The source is divided into bounded leaves; each leaf preserves every segment ID and text and cites both temporal endpoints. The UTF-8 byte reservation is an app estimate, not a tokenizer count. No automatic retry follows an uncertain dispatch.

After all section reports are saved, `/groq-full-coverage-global` builds evidence notes from the complete ordered sections, then runs a bounded binary synthesis tree. Each node is a separate model request and saved operation, with a bounded quote, fresh Free credential binding, 6,600 token reservation, shared 61 second pacing and 195,000 rolling day app cap. A day-limit response leaves durable progress for a later approval and window. The root is a new model answer, distinct from the chronological section appendix. Citations, numbers and quotes are checked against the stored source; whole-video semantic completeness remains human unreviewed. The final report is written with a single D1 CAS that binds the source, audit, historical operations and usage, section receipts, synthesis nodes and synthesis usage, then read back. TXT export includes root, source coverage and section appendix.

`FAILED_UNCERTAIN` with a complete validated response and exact usage can be reconciled through a separately stored recovery row without a provider call. The original failed row and usage remain unchanged. A pre-dispatch `BLOCKED` node requires a newer approval and a durable review row before a no-call reopen. Neither path retries an uncertain request. D1 triggers lock source, audit and evidence writers while a leaf or synthesis claim/receipt is unsettled. The last fetch guard rechecks the Free binding, credential, source, approvals, receipt proofs and flags. A shared ledger includes `RECEIPT_STORED` reservations.

## Separate imported transcript job

`POST /api/jobs/:id/groq-full-coverage-fresh` accepts an existing owner text/SRT job only after explicit acknowledgement of a **new** summary job, possible duplicate summary tokens and no retranscription. It fixes the original source SHA-256 and segment count, verifies the timestamped transcript's range and stores a deterministic new job ID with an independent source and audit. It copies no old operations or usage. Lost acknowledgement returns the same new ID after readback. The new job's leaf and global paths use their own approvals, checkpoints, usage and report. The original text job and any older audio job remain untouched. The transcript is marked not independently verified against the audio.

This patch requires independent review before any release.

For the locally saved 1,226-segment source, `node scripts/quote-fresh-offline.mjs <source-snapshot.json>` gives a separate SRT job with 31 new leaf calls, 188,486 UTF-8 input-byte reservations plus 21,700 output-token caps, or 210,186 combined reserved units. Each leaf is bounded by 6,200 input bytes and 700 output tokens. The full-coverage manifest caps each validated section at two evidence notes, with each note limited to 1,100 UTF-8 bytes and its source IDs and time range preserved. If more notes are needed, the route stops before synthesis instead of discarding text. The synthesis tree groups up to four notes per call; it sends shared boundary IDs once and each call is bounded by 4,800 input-byte reservation and 1,800 output tokens. Thus 31 sections produce at most 62 notes, 21 synthesis calls and 138,600 additional reserved units: **52 calls and 348,786 reserved units** in total, requiring at least two rolling 24-hour app-cap windows of 195,000 units. With one note per section, the scenario is 11 synthesis calls and 282,786 combined units. This is a finite app reservation bound for source sections that pass the two-note limit, not an exact tokenizer count or proof that the model will fit and produce a valid response. Actual provider usage, account balance, and key to Free organization linkage remain unknown; every call and window requires a fresh approval.
