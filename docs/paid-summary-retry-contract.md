# Separate one-call paid summary attempt

This optional contract is for a job whose first-generation Gemini trial is `CONSUMED`, whose old reservation is `SETTLED` or `RELEASED` without a saved report, and whose first response is not retained for no-call revalidation. A retained complete first response must be revalidated before another provider call is considered. An `UNCERTAIN` or still `RESERVED` first reservation blocks the new attempt.

Migration `0011_paid_summary_retry.sql` adds a separate quote, attempt, and response receipt. The old approval, reservation, receipt, and singleton trial rows are neither reset nor reused. There is one new attempt per job, one quoted provider call, no retry, and no automatic free-to-paid fallback. An expired, cancelled, or released second attempt cannot be replaced through this contract. The second approval can be cancelled only while `APPROVED`, before any send; cancelling the first approval never cancels the separate second attempt. The UI labels and scopes both cancellation controls. Status exposes both ledgers and labels provider invoice amount `UNKNOWN`; when the second ledger cannot be read, the saved report shows an unknown cost state rather than inferring settlement from the first ledger; the token-derived estimates do not claim to be invoice amounts.

Quote binds the complete source snapshot, exact wire request, catalog model and price version, credential generation, prior reservation, one-call maximum of 720896 microUSD, and expiry. Approval and execution compare the entire stored quote JSON with a fresh catalog quote, including amount and unit prices; the stored hash column alone is insufficient. Approval requires confirmation that the first cost remains. Execution requires the ordinary paid runtime gates, an atomic `APPROVED` to `RESERVED` claim, and a final source, key, prior-ledger, and expiry check immediately before provider fetch. A predispatch rejection releases the new reservation; an uncertain send stays reviewable. Full provider HTTP response bytes (up to 256 KiB) are hashed and read back before report validation. A stored complete response can be revalidated with zero provider calls, including a `RESERVED` attempt interrupted after receipt storage; its unsettled cost remains `REVIEW_REQUIRED` until independently reconciled. Revalidation does not change either cost ledger. Job deletion scrubs retained response text and hash.

Activation sequence is separate from this implementation: review migration and code; apply migration only after approval; verify current model access for the stored key/project, current catalog price, applicable tax ceiling, and existing prepaid balance; then deliberately enable the ordinary paid gates. Keep `ALLOW_PAID_API=false` and owner-only Access. No production migration, gate change, model call, deployment, or data deletion is part of this branch change. The UI shows both costs and requires a fresh explicit click for quote, approval, and execution.
