# 숫자 근거 검증 설계 (v1 8단계)

- 작성일: 2026-11-21
- 상태: **초안 — 사용자 확인 대기**
- 관련: `docs/v1/DESIGN.md` 5장 8단계

## 1. 목표

요약에 나온 **모든 숫자**가 원문(전사문)과 같은 뜻인지 자동으로 확인하고, 숫자마다 결과를 화면에 표시한다.

잡아내야 할 왜곡:

| 코드 | 예시 (원문 → 요약) |
|---|---|
| `VALUE_CHANGED` | 20% → 25% |
| `UNIT_CHANGED` | 20%p → 20%, 300만 원 → 300만 달러 |
| `SCALE_CHANGED` | 1.2억 → 1.2만 |
| `QUALIFIER_CHANGED` | 약 20% → 20% 이상 |
| `KIND_CHANGED` | 비중 20% → 증가율 20% |
| `NO_EVIDENCE` | 원문에 없는 숫자 |
| `QUOTE_NOT_FOUND` | 근거로 든 문장이 원문 구간에 없음 |

## 2. 이전 패키지와의 차이

업로드된 `video-summary-fixture-readback`의 숫자 비교기는 `○○ 비중은 약 20%다.`처럼 정해진 문장 틀 하나만 판정한다. 실제 요약 문장은 거의 판정 불가가 된다. 새 설계는 **문장을 해석하지 않고**, 모델이 숫자를 정해진 형식으로 따로 내게 한 뒤 코드로 대조한다.

| | 이전 | 새 설계 |
|---|---|---|
| 판정 대상 | 문장 전체가 틀에 맞을 때만 | 요약에 나온 숫자 전부 |
| 근거 | 호출자가 맞춰 준 근거 1개 | 모델이 낸 구간 ID + 원문 인용 |
| 판정 방식 | 문장 정규식 | 숫자 추출·정규화 후 값·단위·한정어·지표 대조 |
| 언어 | 한국어 틀만 | 한국어 요약 ↔ 한국어·영어 원문 |
| 결과 | 통과 / 판정 불가 | 숫자마다 확인 / 불일치 / 확인 불가 + 원문 위치로 이동 |

**업로드 패키지 처리**: 저장소에 넣지 않는다. 다만 예시 30쌍(`synthetic-cases.json`)은 새 형식으로 바꿔 회귀 테스트 자료로 재사용한다. 필요한 사례는 이 문서에 의미만 옮겨 적고, 원본 파일은 사용자 PC에 그대로 둔다.

## 3. 방법

### 3.1 요약 출력 형식 (모델이 냄)

요약 항목과 챕터마다 `facts` 배열을 붙인다. 문장에 숫자가 있으면 반드시 `facts`에 넣도록 스키마와 지시문으로 강제한다.

```json
{
  "text": "국내 매출 비중은 약 20%로 늘었다.",
  "facts": [
    {
      "surface": "약 20%",
      "value": 20,
      "unit": "PERCENT",
      "qualifier": "APPROXIMATE",
      "kind": "SHARE",
      "subject": "국내 매출",
      "segmentIds": [41, 42],
      "quote": "국내 매출 비중이 한 이십 퍼센트 정도 되고요"
    }
  ]
}
```

- `quote`는 원문에서 **그대로 복사한** 짧은 구간이어야 한다.
- 원문이 영어면 `quote`도 영어 원문 그대로 둔다(번역 금지).

### 3.2 코드 검사 (모델 호출 없음, 결정적)

숫자 하나당 아래 순서로 검사한다.

1. **누락 검사**: 요약 `text`에서 숫자를 직접 추출한다. `facts`에 없는 숫자가 있으면 `NO_EVIDENCE`.
2. **구간 검사**: `segmentIds`가 실제로 있는지, 해당 챕터 시간 범위 안인지 확인한다.
3. **인용 검사**: `quote`가 해당 구간(앞뒤 1구간 허용) 원문에 있는지 확인한다. 띄어쓰기·문장부호 차이는 무시하고, 없으면 `QUOTE_NOT_FOUND`.
4. **값 검사**: `quote`에서 숫자를 추출·정규화해 `value`, `unit`, 규모(만·억·million 등)를 비교한다.
5. **한정어 검사**: 숫자 주변의 약·대략·정도·가량·이상·이하·초과·미만·최대·최소(영어 about, roughly, at least, more than, under, up to)를 비교한다.
6. **지표 검사**: 비중·점유율·증가율·감소율·성장률(영어 share, growth, increase, decline)을 비교한다. 원문에 지표 단어가 없으면 실패가 아니라 "확인 불가"로 둔다.

### 3.3 숫자 정규화 범위

| 형태 | 예시 | 정규화 |
|---|---|---|
| 아라비아 숫자 | `1,234`, `3.5`, `20%` | 그대로 |
| 한국어 규모 | `1.2억`, `300만`, `3조 5천억` | 정수로 환산 |
| 한국어 수사 (전사문) | `이십 퍼센트`, `삼백만`, `한 이십` | 20, 3,000,000, 약 20 |
| 영어 (전사문) | `twenty percent`, `1.5 million`, `a third` | 20%, 1,500,000, 1/3 |
| 단위 구분 | `%` vs `%p`(퍼센트포인트), `배`, `원/달러`, `명`, `년` | 다른 단위로 취급 |

연도·날짜·시각(2024년, 3월, 10시)과 챕터 번호처럼 사실이 아닌 숫자는 따로 분류해 값 검사만 한다.

### 3.4 결과와 화면 표시

- 숫자마다 결과를 하나씩 매긴다.
  - `VERIFIED`: 원문 확인
  - `MISMATCH`: 위 코드 중 하나
  - `UNVERIFIABLE`: 확인 불가 + 이유
- 화면에서 숫자 옆에 ✓ / ⚠ / ? 표시를 붙인다. 누르면 근거 구간 원문과 YouTube 해당 시각으로 이동한다.
- 보고서 상단에 "숫자 N개 중 확인 X, 불일치 Y, 확인 불가 Z"를 보여 준다.
- **저장을 막지 않는다.** 표시만 한다.
- `MISMATCH`가 있는 요약 항목은 오류 내용을 알려 주며 그 항목만 **1회 자동 재생성**한다(무료 범위). 재생성 후에도 남으면 ⚠로 둔다.

### 3.5 하지 않는 것

- 문장 전체 의미가 원문과 같다고 보증하지 않는다(숫자 대조만 한다).
- 외부 사실 확인(원문 숫자 자체가 맞는지)은 하지 않는다.
- 다른 모델로 2차 판정하는 방식은 무료 한도를 쓰고 결과가 매번 달라서 1차에서는 쓰지 않는다.

## 4. 앞 단계에 미리 넣을 것 (권장)

3단계 요약 엔진의 출력 스키마에 처음부터 `facts`(값·단위·한정어·구간 ID·인용)를 넣는다.

- 추가 비용이 거의 없다.
- 8단계에서 이미 저장된 보고서도 다시 생성하지 않고 검증할 수 있다.
- 3단계에서는 형식만 검사하고, 판정 로직과 화면 표시는 8단계에서 붙인다.

## 5. 완료 기준

| 항목 | 기준 |
|---|---|
| 회귀 테스트 | 이전 예시 30쌍(새 형식으로 변환) + 전사문 형태 예시(한국어 수사, 영어 원문, %p, 억·만, 한 문장 여러 숫자) 전부 예상대로 판정 |
| 누락 방지 | 요약에 숫자가 있는데 `facts`가 비어 있으면 반드시 `NO_EVIDENCE`가 나오는 테스트 통과 |
| 실제 영상 | 6단계 실제 영상 3개 결과에서 **숫자의 80% 이상이 판정 가능**(확인 또는 불일치) |
| 오판 | 실제 결과 중 숫자 20개를 무작위로 골라 사람이 확인했을 때 잘못된 불일치 2개 이하 |

## 6. 남은 이슈

1. 실제 전사문에서 숫자가 어떻게 나오는지(아라비아 숫자인지 한글 수사인지)는 제공자마다 다르다. 6단계 실제 결과를 보고 정규화 규칙을 보강한다.
2. "판정 가능 80%"와 "오판 2개 이하"는 초기 목표치다. 실제 결과를 본 뒤 조정할 수 있다.
