## 2. v1 설계에 반영한 것

1. **기존 전사 우선 재사용**: 전사 확보 순서 맨 앞에 "운영 D1에 같은 영상 ID의 기존 전사가 있으면 재사용"을 추가한다. 98분 예시는 다시 전사하지 않고 기존 1,226개 세그먼트로 요약한다.
2. **출력 순서**: 핵심 결론 → 타임스탬프별 한 줄 요약(챕터) → 상세 주장·인과·맥락.
   - 1차(3단계)는 앞의 두 가지를 만든다.
   - 세 번째(상세 주장·인과·맥락)는 8단계 분석에서 만든다.
3. **화면에 출처 구분 표시**: 전사 출처(기존 자막 / Gemini 전사 / PC Whisper / 업로드), 전사 범위(전체·일부), 요약 생성 경로, 저장 시각을 결과 화면에 표시한다. 일부만 전사된 경우 "전체 완료"로 표시하지 않는다.
4. **자동 요약과 수동 교정 분리**: 자동 생성 요약과 사람이 고친 요약을 다른 레코드로 저장하고, 화면에서도 구분한다.
5. **화자 진술과 AI 해석 분리**: 요약 스키마에서 화자가 말한 내용과 AI 해석을 다른 필드로 둔다. 근거 없는 해석은 넣지 않는다.
6. **배포 전 운영 상태 확인(6단계 선행 조건)**: 운영 Worker의 현재 버전이 main인지 PR #41 계열인지 확인한다. 운영 D1에 `0021` 수동 요약 테이블이 있는지도 확인한다.
   - PR #41 기능(수동 요약 가져오기)이 운영 중이라면, v1 배포로 그 기능이 사라지지 않게 v1 화면의 "이전 보고서" 탭에 함께 보여 준다.
7. **PWA**: 이번 대화에서 사용자가 "PWA 형식 웹앱으로 진행"을 직접 요청했다. 인계 문서가 말하는 "요청 범위 미확인"은 이번 지시로 해소된 것으로 본다. PR #41의 `app.webmanifest`·아이콘·`pwa-install.js`를 참고해 5단계에서 구현하고, Android 실기기 확인 전에는 설치 완료로 보고하지 않는다.
8. **외부 전송 권한**: 인계 문서에는 "공개 URL이라는 이유만으로 외부 provider 전송 권한이 생기지 않는다"는 원칙이 있다. 이번 대화(2026-11-21)에서 사용자가 Gemini URL 입력, Google 무료 등급 데이터 정책, Supadata 사용을 명시적으로 승인했다. 그 승인 범위(공개 영상 요약)로 한정한다.

## 3. 사용자 결정이 필요한 것

1. **재시도 정책 충돌**
   - 인계 원칙: 결과가 불확실한 호출은 자동 재시도하지 않는다.
   - v1 설계: 형식 오류는 1회 재시도하고, Workflow 단계 실패도 자동 재시도한다.
   - 권장안: 무료 제공자에 한해 아래 상한 안에서 자동 재시도를 허용하고, 시도마다 기록을 남긴다. 유료 호출 경로는 없으므로 과금 위험은 없다. 다만 무료 할당량은 소모된다.
     - 응답은 왔지만 형식이 틀린 경우: 1회
     - 네트워크 오류나 429인 경우: 대기 후 최대 2회
2. **로컬 모델(Qwen3-8B) A/B 시험 트랙**
   - 인계 기록상 의미 품질이 불합격이었다.
   - 권장안: v1에서는 요약을 Gemini 무료 등급으로 하고, PC는 전사(Whisper)에만 쓴다. Qwen A/B 시험은 보류한다.
3. **PR #41 처리**
   - 권장안: 병합하지 않고 열린 상태로 둔다. 필요한 부분(PWA 파일, 수동 요약 테이블 읽기)만 v1에서 참고한다.
4. **Windows 로컬 래퍼·대기열 후보**(`D:/CodexWork/...`, 저장소 밖)
   - 7단계에서 PC 실행기를 연결할 때 사용자가 해당 코드를 제공해야 한다. 공개 저장소에 올리지 않는다는 원칙을 유지한다.
   - 권장안: 7단계 착수 때 저장소에 있는 `scripts/local-*`를 기준으로 쓰고, Windows 코드는 필요한 부분만 사용자 확인 후 반영한다.
