# 승인한 네 부분 요약 형식

이 문서는 오프라인에서 개발한 `approved-four-part-v1`의 동작과 검증 범위를 설명한다. 형식 구현은 실제 영상 취득, ASR 완료, 공급자 생성 성공, 운영 저장 성공 또는 의미 품질 검수 완료를 뜻하지 않는다.

## 표시 순서

1. **핵심 결론**을 첫 본문 구획에 둔다.
2. **목차**에는 전사 근거로 계산한 시각, 제목, 개행 없는 한 줄 요약을 둔다.
3. **인과관계 상세 설명**을 관련 목차와 전사 근거에 연결한다.
4. **가정·반례·출처**를 각각 구분하고 관련 목차와 전사 근거에 연결한다.

기존 요약·장별 설명·주장·수치·비판 항목·결론은 보존 부록에서 계속 읽을 수 있다. TXT와 Markdown 내보내기도 같은 읽기용 projection을 사용하며 기존 원본 전사와 부록을 유지한다. 수동으로 가져온 TXT는 기존의 독립 보존 경로를 그대로 사용하며 이 형식으로 자동 변환하거나 재생성하지 않는다.

## 새 보고서 계약

기존 여섯 필드에 `approvedSummary`를 추가한다. 저장 테이블이나 기존 보고서의 형식을 일괄 변경하지 않는다.

| 필드 | 계약 |
|---|---|
| `formatVersion` | `approved-four-part-v1` |
| `keyConclusion` | 본문, 상태, 전사 근거 ID와 정확한 원문 인용 |
| `outline` | 고유 목차 ID, 제목, 한 줄 요약, 전사 근거 ID와 정확한 원문 인용 |
| `causalDetails` | 관련 목차, 상세 설명 또는 `NOT_ESTABLISHED`, 근거 |
| `assumptions` | 관련 목차, 원문에서 밝힌 전제 또는 `NOT_FOUND`, 근거 |
| `counterexamples` | 관련 목차, 원문에서 밝힌 반례 또는 `NOT_FOUND`, 근거 |

자료에 근거가 있는 항목의 `SOURCE_STATED`는 **전사에서 제시한 설명이라는 제출 상태**다. 실제 세계에서 인과관계가 입증되었다는 의미가 아니다. 유효한 전사 번호와 일치하는 인용문만으로 요약 문장의 의미가 참이라고 판정하지 않는다.

자료에서 확인하지 못한 항목은 `자료에서 확인되지 않음`을 명시하고 근거 배열을 비운다. 인과관계나 반례를 형식에 맞추기 위해 만들지 않는다. 인과 설명의 기전 일부를 자료가 설명하지 않았다면 그 한계를 본문에 명시한다. 특정 목차의 세부 범주가 비어 있더라도 미확인 상태로 연결하므로 억지 인과 설명은 필요하지 않다.

모든 목차가 인과·가정·반례 범주에서 각각 참조되었는지 검사한다. 제목은 120자 이내, 한 줄 요약은 500자 이내이며 개행을 허용하지 않는다. 이것은 구조 제약이다. 제목이 정확한지, 한 줄 요약이 충분한지, 원인·과정·결과 설명이 충실한지는 별도 의미 검토 대상이다.

## 시각과 출처의 보존

모델은 시각이나 검증 완료 메타데이터를 생성하지 않는다. 시각은 근거 전사 구간의 시작 시각으로 계산한다. 시각이 없는 전사는 `시각 미확인`으로 표시한다.

검증기는 원문 구간의 ID·시작·끝·본문 전체를 정확한 순서로 SHA-256에 연결한다. 이 binding은 저장 후 원문 변경을 감지하기 위한 것으로 인증 권한, 공급자 실행 영수증 또는 의미 검토 승인을 대신하지 않는다.

재열람 시 원문이 달라졌거나 확인되지 않으면 기존 보고서를 수정하지 않는다. 확인된 시간·원문 링크로 표시하지 않으며, 구조화 본문도 별도의 보존 영역에서 일반 텍스트로 읽을 수 있다. 내보내기에서 기존 보고서 근거에 변경된 전사의 시각을 붙이지 않는다. 현재 전사 자체는 별도 구획에서 보존한다.

출처는 저장된 전사와 그 provenance다. 외부 사실 확인이나 외부 자료 인용을 자동 수행하지 않는다. 부분 전사·전사 공백·경계 불확실성·음성 정확성 미검증 상태를 유지한다. 목차의 마지막 시각이 있다는 사실로 전체 원음의 완전성을 판정하지 않는다.

## 실제로 연결된 생성 경로

기존 일반 Gemini `/summary` 경로에서 명시적으로 새 형식을 선택할 수 있다.

- 계획: `/summary-plan?formatProfile=approved-four-part-v1`
- 실행 본문: `formatProfile: "approved-four-part-v1"`
- 새 분석 화면의 일반 요약은 이 profile을 사용한다.
- 분석 목록에는 새 형식 동작과 기존 형식 재개 동작을 구분한다.

새 profile은 실제 프롬프트 계약과 원문·감사 정보를 별도의 checkpoint identity에 결합한다. 기존 형식의 미완료 단계가 있는 분석에서 다른 형식을 조용히 시작하지 않으며 별도 분석 시도가 필요하다고 차단한다. 실제 전송 직전에도 이 충돌을 확인한다. 이미 저장된 보고서는 덮어쓰지 않고, 요청한 형식과 저장 형식이 다르면 캐시된 기존 보고서임을 표시한다.

기존 요청 형식을 지정하지 않은 호출은 이전 동작과 checkpoint identity를 유지한다. 원래의 입력·출력·무료 할당 제한과 재시도 제한도 유지한다. 상세 구조가 제한을 넘거나 잘못된 응답이 오면 자동 축약·자동 재호출·유료 전환으로 해결하지 않고 차단한다. 긴 자료의 다단계 요약은 현재 제한 안에서 실제 생성 가능한지 추가 검증이 필요하다.

**유료 단일 요약, Gemini 두 단계, Groq 생성 계약은 이번 변경에서 유지했다.** 기존 요청·영수증·승인과 짧은 합성 노드의 제한을 보존하기 위한 범위다. 해당 경로의 저장 보고서는 새 읽기 화면에서 호환 표시하지만, 그 생성기가 새로운 상세 구조를 작성하도록 바뀌었다고 표시하지 않는다. 신규 형식 요청도 실제 공급자 실행은 별도 권한과 기존 게이트를 충족해야 한다.

## 기존 보고서와 재열람

새 구조가 없는 보고서는 읽기 전용 호환 표시를 사용한다. 제목을 추측하거나 일반 주장을 인과관계로 재분류하지 않는다. 중립적인 기존 목차 번호와 기존 본문 발췌라는 표시를 사용한다. 분류되지 않은 항목은 `기존 보고서에 구분 저장되지 않음`으로 표시한다. 이것은 원문을 새로 검토해서 해당 정보가 없다고 판정했다는 뜻이 아니다.

기존 보고서가 현재 저장 전사를 참조할 때에는 저장 당시 원문과 동일하다는 증명이 없다는 점을 표시한다. 보고서 JSON·전사·사용량·공급자 영수증은 조회 시 수정하지 않는다. 소유자 상세 조회와 내보내기만 읽기용 데이터를 계산한다. 기존 인증, 같은 출처 요청 보호, 삭제 정책과 수동 import provenance는 변경하지 않는다.

## 검증과 의미 품질 검토의 구분

자동 검사는 구조, 참조 ID, 원문 인용 문자열, 목차 연결, 시간 출처, source binding, 저장·재열람·내보내기 보존을 검사한다. 결과 메타데이터는 `semanticReview: NOT_PERFORMED`다. 이 값은 합성 테스트가 통과해도 의미 품질 승인으로 바뀌지 않는다.

합성 fixture는 가상 상자의 열 유출 설명과 방문객·판매의 동반 관찰로 구성했다. 실제 영상·사용자 요약·전사·분석 ID를 포함하지 않는다. 독립 읽기 검수에서는 다음을 실제 본문과 대조한다.

- 같은 재료·실내 조건, 구멍 난 뚜껑의 반례와 화자 귀속을 유지하는가.
- 방문객과 판매가 함께 늘었다는 관찰을 입증된 인과관계로 바꾸지 않는가.
- 맑은 날만 관찰했다는 범위와 비 오는 날·작동 과정의 미확인을 보존하는가.
- 근거 인용과 목차, 내보내기, 재열람에 같은 의미가 유지되는가.

별도의 의도적 반대 fixture는 원문에서 인과관계 결론을 내리지 않았는데도 “원인이라고 입증되었다”로 바꾼다. 이 fixture의 참조와 구조가 유효하더라도 독립 의미 검수는 실패해야 한다. 이는 구조 검증의 한계를 드러내기 위한 사례이며 자동 의미 평가기를 구현했다는 주장이 아니다.

로컬 SQLite와 mock 응답으로 저장 후 연결 종료·재개·목록·상세·내보내기를 검증한다. 실제 D1 또는 실제 공급자 성공으로 기록하지 않는다. 실행 환경 때문에 Workerd 등 검사가 실행되지 않으면 통과 수에서 제외하고 별도 제한으로 보고한다.

이 형식 구현은 **자막 없는 영상의 자동 음성 취득이나 ASR 개발 완료를 의미하지 않는다.**
