# Gemini full transcript + source review candidate

This review branch adds a separate Gemini path alongside the existing Groq 79-stage/raw and merge flow. It does not retranscribe audio. The full saved transcript and timed IDs remain unchanged in `yta_sources`; each of the two generation requests receives all original segment texts and IDs. The second request also receives the first report. Its JSON verdict and categorized suspected omissions or distortions are retained separately.

**No provider call, paid generation or payment was performed during local validation.** The route is disabled by default (`ENABLE_GEMINI_TWO_PASS` must be `true`). Migration `0015_gemini_two_pass.sql` must be reviewed and applied separately before the route can be used. The known registered Gemini project was observed on 2026-10-13 as Tier 1 paid; no free allowance is established. A paid-project countTokens quote requires the base feature flag, verified model access, `ALLOW_PAID_API=false`, and explicit transcript-transmission consent. It does **not** enable paid generation. A free run is blocked unless a *different, verified free project* is explicitly configured with `GEMINI_PROJECT_BILLING_MODE=FREE`, `GEMINI_TWO_PASS_FREE_PROJECT_ATTESTED=true`, and existing free-only guards. The UI for the current project presents the paid path only. Paid execution additionally requires `ENABLE_GEMINI_TWO_PASS_PAID=true`, `GEMINI_TWO_PASS_PAID_EXECUTION_APPROVED=true`, verified model/tax gates, `ALLOW_PAID_API=false`, and this path's exact, separate D1 approval. The earlier Groq raw authorization does not apply.

`models.countTokens` receives the full `generateContentRequest`, including the original transcript and segment IDs, before a quote is stored and before each generation dispatch. [Google's token API](https://ai.google.dev/api/tokens) states that this form includes the prompt and steering information. The UI and server require a separate, explicit full-transcript transmission consent before quoting; it is distinct from the later paid-generation approval. A successful run sends three token-count requests and at most two generation requests. The quote binds the consent, source hash, prompt audit, first request hash, model, credential generation, official input count, input cap, output cap, two calls, zero retries, price version, amount, project mode and expiry. The per-call input cap is the first official count plus 16,384 tokens, limited to 120,000. The second request is counted after the first report exists; if it exceeds that preapproved cap, no second generation is sent. This 16,384 allowance is a *chosen execution ceiling*, not a token estimate or a claim that the second request will fit. The output request cap is 8,192 tokens for each call. At the fixed catalog rates, the two-call pretax cap for the approved token range is computed separately from a 100% tax uncertainty buffer. A preflight count beyond the approved range prevents dispatch; excessive or inconsistent response usage is retained and blocks further generation. The app amount covers only calls and token ranges allowed by these guards, not a verified provider invoice, KRW amount, or a promise about charges outside the provider's reported usage and documented billing rules. A `countTokens` API request is a separate provider request and is **not** a generation or a free-project attestation.

Each phase has a unique D1 reservation keyed by job and phase. The reservation is inserted before the job's pending transition. A reservation still in `RESERVED` can be released without a provider call after a transition failure; the final atomic claim moves it to `DISPATCHING` only after checking the saved source, audit, approval, request, expiry, deletion marker and exact credential row. An uncertain dispatch cannot be retried. A repeated POST cannot make the same generation call. The response body is stored with its hash and byte length before JSON parsing, validation or report save. A failed receipt write is read back against that exact response and retried once locally without another provider call. Incomplete responses remain incomplete; they cannot be treated as a complete receipt. Status is read-only. Recovery recomputes the source, prompt audit and exact request hash before attaching a saved response. A complete stored response can be revalidated without a provider call, including when the final D1 usage update failed after the report was saved. The second phase cannot start until the first receipt and usage ledger are settled. Once settled, the owner can cancel the remaining second call; a cancellation racing its token count prevents the D1 dispatch transition. Expired or cancelled quotes can receive a fresh revision only when no phase reservation exists. A failed or cut-off second response leaves the first report and both call records visible, with no automatic third call or paid fallback. Deletion removes the two-pass private reports and receipts after the deletion tombstone; a late response cannot write past that tombstone.

The first report receives deterministic schema, evidence-reference, number, direct-quote and broad time-window checks. The second model checks the complete transcript against the first report for omitted distinct claims, counterexamples, numbers, negation, uncertainty, causality, quotations and evidence IDs. Suspected items are shown to the owner. Even a `PASS` remains a stored draft with `sourceReview: REQUIRED`; it cannot promote the public job to a completed report. Model judgment cannot prove full semantic coverage, original audio accuracy or external facts. A person must inspect the original transcript and suspicious ranges for stronger assurance. The Groq path remains available and retains its different all-segment coverage manifest and detailed stage appendix.

Review tests use mock generation and local SQLite/Workerd D1 only. The synthetic 1,226-segment fixture carries distinct numerical, date, duration, negation, uncertainty, causal and counterexample phrases into both requests. Tests also exercise an issues verdict, output truncation, changed source, duplicate POST, paid/free mode separation, receipt retention, draft retention and TXT export. The tests cannot establish that Gemini will faithfully identify every omitted meaning on the real video.
